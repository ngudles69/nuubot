runtime flow compare

Current code shape in nuubot/core/runtime.py and nuubot/core/clock.py. This page compares what happens today, not the future target design.

aligned workflow

# shared intent paper/live path backtest path comment
1 Load config. load_botrun_config() load_botrun_config() Same path.
2 Create runtime objects. Clock, PaperData, signaler, risk, executor. ReplayClock, BacktestData, signaler, risk, executor. Mode split is in object construction.
3 Initialize components. Runtime.init() Runtime.init() Same lifecycle call.
4 Start data. PaperData.start() starts websocket task. BacktestData.start() no-op. Live data arrives in background. Backtest data is already loaded.
5 Seed signalers with closed history. PaperData.history() fetches closed candles from Hyperliquid REST. BacktestData.history() returns bars before replay cursor. Same runtime call. Different data ownership.
6 Mark latest seeded closed bar as processed. Set last_bar_ms to latest seeded bar. Set last_bar_ms to latest seeded bar. Prevents acting on seed bars later.
7 Run loop driver. Clock.run() sleeps until timer and dispatches loop_once(). Runtime.loop_backtest() reads next replay timestamp. Primary control-flow split.
8 Move clock forward. Clock.tick() sets now_ms from wall clock. ReplayClock.advance(ts_ms) sets now_ms to replay time. Backtest does not sleep.
9 Prepare market state for this loop. Websocket has already updated latest_bbo/latest_bar. Current code still calls no-op PaperData.ingest(). Current code calls BacktestData.ingest() to move replay cursor into current_bar. Name is confusing. In backtest this means replay select, not ingest.
10 Snapshot market. PaperData.snapshot(now_ms) returns latest buffered BBO/bar. BacktestData.snapshot(now_ms) returns current replay bar. Same runtime call.
11 Skip invalid or unwanted bar. Skip missing bar, duplicate closed bar, or partial bar unless a signaler has partial = true. Skip missing bar or duplicate closed bar. Backtest bars are closed.
12 Process risk. risk.score(), risk.exit() risk.score(), risk.exit() Same path.
13 Process signal. signaler.loop_once(bar) signaler.loop_once(bar) Same path. EMA mutates only on closed bars by default.
14 Process executor. executor.loop_once(bar, signal) executor.loop_once(bar, signal) Same path.
15 Exit checks and telemetry. Can exit on max loop, risk, signaler, max cycles, manual stop later. Logs live telemetry each loop. Can exit on no market, max loop, risk, signaler, max cycles. Same core checks; telemetry verbosity differs.
16 Stop and result. Stop signalers/risk/data, close active executor state, write results. Stop signalers/risk/data, close active executor state, write results. Same path.

current branch map

flowchart TD
  A[load config] --> B[create Runtime]
  B --> C[init]
  C --> D[start]
  D --> E[seed signalers]
  E --> F{exec_network == backtest?}
  F -- no --> G[Clock.run]
  G --> H[Clock.tick wall time]
  H --> I[dispatch loop_once]
  F -- yes --> J[loop_backtest]
  J --> K[next_ts_ms]
  K --> L[ReplayClock.advance]
  L --> M[BacktestData.ingest selects current_bar]
  M --> I
  I --> N[process_market snapshot]
  N --> O[skip missing duplicate partial]
  O --> P[risk]
  P --> Q[signaler]
  Q --> R[executor]
  R --> S[telemetry / exit]
  S --> T[stop / results]

Current concern: BacktestData.ingest() is named like live ingest, but it currently means "select next replay bar". That is likely the first naming/ownership cleanup before deciding whether separate runtimes are needed.
